==================================================
一、第一批人工听感结论
==================================================

以下结论来自真实复刻音色 + cosyvoice-v3.5-plus + 人工试听。

--------------------------------
Case 01｜纯克隆基线
--------------------------------

结果：
- 当前反而是整批中相对最自然的一类；
- 真人感 4/5，自然度 4/5；
- 仍有明显AI/TTS念稿感；
- 节奏整体偏平；
- 重点不明显；
- 销售感偏弱；
- 但明显优于复杂 instruction 版本。

特别观察：

用户认为：
“发音过于标准”本身可能就是AI感来源之一。

真人说话可能需要：
- 不完全标准的音节完成度；
- 轻微连读；
- 某些字自然带过；
- 轻微口语粗糙感；
- 不要每个字都像语文标准朗读。

需要把这一维度正式加入：

【发音完成度 / 口语粗糙度】

注意：
这不是让模型念错字，
也不是软件伪造口音参数。

它属于导演意图 / E2语义控制，
当前没有精确硬参数。

--------------------------------
Case 02｜短 instruction
--------------------------------

结果：
- 与 Case01 相比变化明显；
- 但反问刻意；
- 重音过猛；
- 情绪过度；
- 局部变化突兀；
- 销售感太硬；
- 真人感反而下降。

结论：

Instruction 可以改变表演，
但不能因为“能改变”就认为“适合生产”。

生产规则：

默认禁止复杂表演 instruction。

如果使用：
- 必须极短；
- 一次只表达一个核心状态；
- 不堆多个情绪形容词；
- 不同时要求反问 + 兴奋 + 重音 + 销售感 + 节奏变化。

--------------------------------
Case 03｜长 instruction
--------------------------------

结果：
- 明显播音腔；
- 做作；
- 节奏突兀；
- 情绪不自然；
- 真人感 1/5。

结论：

长复杂 instruction 在当前真人带货生产中应视为高风险能力。

即使官方允许100 weighted chars，
也不代表产品应该充分使用上限。

请增加：

PRODUCT_RECOMMENDED_RANGE

推荐值应显著短于官方硬上限。

具体推荐长度先基于本轮经验设计，
不要冒充官方限制。

官方100 weighted仍保留为 MODEL_HARD_LIMIT。

--------------------------------
Case 04｜instruction 101超限
--------------------------------

技术结论：

- 本地成功拦截；
- 未发云端；
- 该能力属于协议安全校验通过。

这是技术通过项，
不属于真人听感项。

--------------------------------
Case 05｜单 speak
--------------------------------

结果：
- 尚可；
- 与基线相比没有明显核心收益；
- 节奏变慢；
- 情绪仍平。

结论：

single <speak> 可作为结构载体使用，
但不应被描述为“提升活人感能力”。

--------------------------------
Case 06｜break 400ms
--------------------------------

结果：
- 停顿确实发生；
- 但400ms偏长；
- 听感刻意；
- 情绪错位；
- 真人感没有提升。

结论：

SSML break 属于 E0 / 精确结构能力，
但：

“精确执行 ≠ 自然”。

新增生产原则：

停顿数值必须首先服务语义，
不能为了“让真人感更强”机械加长停顿。

默认应优先短停顿。

不要把 400ms 当成常用模板值。

--------------------------------
Case 07｜instruction + SSML
--------------------------------

结果：
- 比单独 break 更做作；
- 情绪不符合当前卖货节奏。

结论：

多个控制能力叠加不会自动提高真人感。

新增原则：

【控制叠加惩罚原则】

每增加一个控制层，
都必须证明带来真实听感收益。

禁止为了“更精细”同时叠：
instruction
+ SSML
+ rate
+ pitch
+ 多 speak

--------------------------------
Case 08｜连续多个 speak
--------------------------------

结果：
- 明显拼接感；
- AI/TTS感增加；
- 节奏太平；
- 能量/人物状态不连续；
- 销售感生硬。

结论：

连续多 <speak> 虽然技术接受，
但当前在真人带货主链中：

PRODUCT_DISABLED_BY_DEFAULT

不是 MODEL_UNSUPPORTED。

Capability Profile必须区分：

MODEL_SUPPORTED = true

PRODUCT_ENABLED = false

reason =
“真人连续表达产生明显拼接/能量断裂风险”

只有明确实验场景才允许开启。

--------------------------------
Case 09｜局部 rate=0.85
--------------------------------

结果：
- 像人为拉慢；
- AI感增强；
- 重点位置错误；
- 情绪错位；
- 能量跳变。

结论：

局部 rate 虽然 API 支持，
但当前不适合作为真人节奏设计工具。

生产规则：

默认禁止使用明显局部 rate 改变来制造表演。

除非用户明确实验或特殊发音需求。

特别注意：

用户真正想要的不是：

“某一段机械变慢”

而是：

“真人销售节奏发生变化”。

这是完全不同的目标。

--------------------------------
Case 10｜局部 pitch=1.1
--------------------------------

结果：
- 明显AI感；
- 不适合真人口播。

结论：

局部 pitch 用于制造情绪：

PRODUCT_DISABLED_BY_DEFAULT

保留模型支持事实，
但编译器禁止自动使用它表达：
- 激情
- 惊叹
- 调侃
- 重音
- 高潮

--------------------------------
Case 11｜sub
--------------------------------

结果：
- 不提升活人感；
- 只应作为文本/读法纠正能力。

结论：

sub：
E0文本/发音工具。

禁止拿它承担表演控制。

--------------------------------
Case 12｜say-as cardinal
--------------------------------

结果：
- 读法存在异常风险；
- 整体平；
- 销售表达不自然。

结论：

say-as只能解决“语义/数字怎么读”。

不得用于：
- 制造价格高潮；
- 制造数字卖点；
- 提升销售感。

数字“怎么卖”必须和数字“怎么读”区分。

--------------------------------
Case 13｜phoneme
--------------------------------

结果：
- 发音控制有价值；
- 这一组相对自然；
- 但前段仍平。

结论：

phoneme保留。

角色：

只做发音修正。

不能承担：
- 情绪
- 节奏
- 销售感

--------------------------------
Case 14｜同 seed 重复
--------------------------------

结果：
- 与 Case02 几乎一致。

结论：

seed 对复现已有版本有实际价值。

保留：

- A/B
- 复现
- Golden版本
- 修复比较

但不要声称 seed 可以解决真人感。

--------------------------------
Case 15 / Case16｜纯文本基线
--------------------------------

结果：
- 仍有AI/TTS感；
- 念稿；
- 节奏平；
- 重点错误；
- 销售节奏不足。

说明：

当前问题并不是“缺少更多参数”。

即使不加参数，
CosyVoice自身仍存在：
- 语音过于标准；
- 重音语义理解不足；
- 销售节奏理解不足；
- 真实人类临场表达不足。

因此：

系统目标不能变成“不断叠控制参数”。

==================================================
二、正式增加：
Naturalness First 原则
==================================================

把以下原则提升为 ChatGPT协议编译规范的最高优先级之一：

【Naturalness First / 最小干预原则】

ChatGPT编译导演意图时，
必须按以下优先顺序尝试：

第一优先：
原始连续文本 + 模型自然生成

第二优先：
只使用标点 / 文本结构 / 极短Instruction

第三优先：
必要SSML结构控制

第四优先：
特殊发音工具
phoneme / hot_fix / sub / say-as

最后才考虑：
rate / pitch / 多speak等高风险控制

原则：

不是问：
“我还能增加哪些控制参数？”

而是问：
“实现这个导演意图，最少需要多少控制？”

如果基线已经较自然：
宁可少调，不要多调。

==================================================
三、增加：
控制复杂度风险等级
==================================================

建议增加：

CONTROL_COMPLEXITY

L0
纯文本/默认生成

L1
极短Instruction或单一安全结构控制

L2
Instruction + 单一SSML控制

L3
局部rate/pitch/多speak/多层叠加

生产规则：

默认优先 L0/L1。

L2必须有明确理由。

L3默认禁止自动编译，
必须用户显式开启实验模式。

==================================================
四、重新定义“活人感”
==================================================

在现有维度：

1. 语义停顿
2. 速度变化
3. 重音层级
4. 情绪变化
5. 聊天/临场感
6. 人物连续性
7. 销售能量曲线
8. CTA自然度

基础上正式增加：

9. 发音完成度 / 口语粗糙度

定义：

真人并不会把每一个字都完整、标准、等权重地朗读出来。

关注：

- 连读
- 轻读
- 自然带过
- 句尾弱化
- 音节完成度变化
- 轻微口语习惯
- 非播音式标准发音

注意：

当前 CosyVoice 没有对应硬参数。

必须标记为：

E2 SEMANTIC / DIRECTOR INTENT

不得伪造参数。

五、正式增加导演词条
==================================================

把以下真实用户表达正式加入
《ChatGPT真人口播导演意图沟通手册》。

--------------------------------
词条：
诊断式确定感
--------------------------------

用户描述：

“像一个有经验的老医生看完以后，已经知道问题在哪里，然后平静但非常确定地告诉你。”

不是：
愤怒
喊
播音
强重音

适合：

“你就是坚持不了。”

核心：

- 低表演感
- 高确定性
- 平静
- 稍微收住
- 重点明确
- 不夸张

执行可信度：

E2

优先：
短Instruction近似

禁止：
高pitch
过度重音
强情绪词堆叠

--------------------------------
词条：
节奏型销售排比
--------------------------------

真实需求示例：

懒宝宝 → 高一点能量、快速抓注意
早上喝 → 回正常节奏、答案清楚

馋宝宝 → 再次提气
中午喝 → 回正常

又懒又馋，一天两杯 →
快速、集中、达人直播间式收束

注意：

这是“节奏结构”，
不是机械 rate 改速。

当前不应自动编译成：
rate=0.85 / 1.2

主要属于：
导演意图层。

--------------------------------
词条：
稳 → 推 → 爆 → 松
--------------------------------

用于价格段：

专研配方
→ 认真可信

一杯不到一块钱
→ 开始加强销售推动

99块到手100杯
→ 价格高潮 / 惊叹

每天喝也不心疼
→ 立即卸掉卖货力，像随口告诉用户

特别重要：

最后一句不是继续高潮。

这是典型真人销售节奏。

不能把四句话都用同一种“促销声音”念。

==================================================

“这里更激情”
“这里更快”
“这里更有价格爆点”

DIRECTOR INTENT

然后优先通过：

- 文本结构
- 标点
- Window边界
- 极短Instruction

进行近似。

只有用户明确要求：
“我要测试参数变化”

才允许进入高风险参数控制。
