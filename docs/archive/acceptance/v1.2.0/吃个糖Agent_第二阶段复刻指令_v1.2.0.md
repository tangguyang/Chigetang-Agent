# 吃个糖 Agent｜第二阶段复刻指令 v1.2.0

**必需输入：**经用户明确确认的第一阶段核对稿、当前软件导出的《标准ZIP任务包规范 v1.2.0》及全部真实素材。第二阶段必须严格依 v1.2.0 规范，不自行增加 manifest 字段；无法执行真实 Windows 导入测试时，明确仅为静态/非付费校验。

## 第二阶段｜用户确认后制作标准 ZIP

**唯一触发条件：** 用户已就最终人物、产品、背景、分段、Prompt、参考素材和生成参数明确确认。没有确认时，只能修改第一阶段核对稿，不得正式打包。确认后冻结方案，避免打包时自行改写 Prompt 或换图。

## 12. 确定软件协议并冻结输入

- 读取与本次软件版本匹配的《ChatGPT 任务包规范》，核对 `schema_version`、`package_type`、`manifest.json` 字段、大小与数量限制、Prompt Token 转换及当前模型参数。**不得把本文档的叙述当作机器 Schema，也不得从记忆推断未声明字段。**
- 锁定用户确认的原始视频、完整克隆音频、人物／产品母图、动作参考切片、每段有效参考音频、每段 Prompt、分段边界与后期合成说明。每段都对应原片绝对时间与片段相对时间。
- 如最终素材与核对稿不一致、确认后出现新限制或某个引用文件缺失，明确列出变更并重新请求用户确认；不要静默替换。

## 13. 准备真实素材与每段任务

1. 从确认后的原片制作实际可读取的参考视频文件，并检测真实时长、格式、尺寸及必要的帧率信息；按每个片段的实际语音区间准备对应参考音频，不得让后续片段误用第一段音频。保留剪映克隆**完整音频**供最终成片，默认不将其整个上传 Wan。
2. 为各段准备 UTF-8 的独立 Prompt。对**每个实际参考切片**抽查首／中／尾及烧录文字高风险区间，不能仅凭负向 Prompt 声称无字。正式 Prompt 只写镜头、时间轴、动作、口型状态、重音、表情和情绪，**不写逐字台词**；明确保留手部禁令：无美甲、无长指甲、无戒指、无手镯、无手链、无珠串或其他首饰；指甲短、自然。
3. 第一阶段的原片绝对区间与每段音频区间必须已经确认；实际参考片要**先裁剪后加入 ZIP**，并检测裁剪文件时长。`source_range_ms` 仅记录片段原片来源区间（毫秒），**导入器不会依据此字段自动裁剪原片**。原始视频和分析图默认不打包；完整克隆配音默认在 ZIP 外供剪映。确需附加文档或后期文件时，必须按规范逐文件声明，不能放入未声明的 analysis 文档。
4. 单段任务和多段任务均按任务包规范使用同一套 `segments` 结构：一个片段即单条生成，多个片段即长视频任务组。每段各自拥有实际时长、Prompt 和需要的参考视频／参考音频；人物与产品可按协议共享。

## 14. 建立素材 ID、@引用和 manifest

- 按软件规范为真实文件生成唯一素材 ID、ZIP 相对路径、类型、用途及**真实文件字节**的 SHA-256。`bindings` 的键不带 `@`，例如 `"person":"person.main"`；仅 Prompt 正文写 `@person`，正式协议 1.2.0 不允许 `reference_order`。标准别名 `person/product` 只能指向 image、`motion` 指向 video、`voice` 指向 audio；其他合法自定义别名按真实素材类型分配槽位。不要用示例、占位哈希或并不存在的路径冒充正式数据。
- 为 Prompt 中每个 `@人物母图`、`@产品主图`（如使用）、`@动作视频`、`@克隆音频` 等别名建立**当前片段的精确映射**。不要依靠文件名模糊匹配；不允许未声明引用、类型不符、重复歧义或未使用的声明引用。
- 按 **Prompt @引用 → 当前片段 bindings → 素材 ID → 真实文件 → type/usage → Wan @ImageN/@VideoN/@AudioN** 逐段核验，确认共享引用和逐段覆盖不会串段；统一参考顺序与软件实际支持的参考槽位，确保人物图、产品图、动作视频和克隆音频不会交叉绑定。提示词内的语义别名必须由导入器转成真实素材绑定，而不只是传递文字。
- `manifest.json` 只能填写软件实际支持的字段和合法参数，记录各段 `order`、`prompt_file`、输出时长及按需的来源时间范围；可选文件、后期完整音频和合成顺序依照规范填写。

## 15. 正式打包前检查

- 检查 ZIP 根目录存在 `manifest.json`；Prompt、素材及所声明文档路径均真实存在；使用规范要求的 UTF-8、相对路径和合法压缩格式。
- 对全部文件计算并复核真实 SHA-256；检查文件大小、类型、各段真实参考视频总时长 ≤15 秒、总视频参考 + 本段输出 ≤30 秒；参考音频独立验证时长/数量。`shared.params.duration` 仅允许 -1 或整数 2–30，段级 `duration_seconds` 仅允许整数 2–30；还要通过实际模型 durationOptions。已冻结的时长如不受支持，先重新确认，不暗改参数。
- 逐段解析 Prompt 的所有 `@引用`，核对 ID → 文件 → 用途 → 参考槽位一致。`analysis_only`、`postproduction_only` 文件不得被误绑定到 Wan。
- 对 ZIP 执行 CRC、UTF-8、文件路径、重复条目、文件声明、SHA-256 及解压完整性检查。**若可用当前版本真实生产解析器，执行非付费校验；静态 ZIP 校验、源码生产解析器通过、Windows UI 实际导入、真实 Wan 云端生成是四个不同层级，必须逐项单独报告。**
- 发生缺失、冲突、校验失败或模型参数不可用时，停止交付可执行包，列出具体问题，不假装生成已完成。

## 16. 第二阶段交付

仅在文件真实生成且检查通过后，提供正式 ZIP 下载链接，并简要说明：任务名称、片段数量、各段输出时长、使用的参考素材、完整克隆音频如何供剪映合成、执行的校验及尚未验证的内容。不给出无依据的“100%复刻成功”承诺。

**最终执行规则：** 用户给素材和要求 → ChatGPT 逐帧分析与提交核对稿 → 用户确认 → ChatGPT 依当前软件规范制作并校验标准 ZIP → 用户导入吃个糖 Agent，一键生成视频；最终完整克隆配音仍由剪映合成（除非用户另外确认新的合成工作流）。
