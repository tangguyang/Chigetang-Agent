# 吃个糖 Agent v1.2.9 修复版2｜真人口播最终开发需求 V1.0

> 分支：dev  
> 版本：v1.2.9 修复版2  
> 范围：仅重构“真人口播”模块，不破坏旧音频生成、复刻音色、视频生成、一键生成/一键复刻等既有功能。

## 0. 成功标准

这次修复的目标不是增加更多功能，而是把真人口播做成一个不会卡死、可以持续修改、可以反复生成、可以人工接管的生产工具。

必须满足：

1. 用户能完成：创建任务 → 导入方案 → 修改 → 保存 → 单段生成 → 再修改 → 再生成 → 选版本 → 拼接。
2. 任意阶段都允许人工修改，不强制回到 ChatGPT。
3. ChatGPT 是导演和诊断助手，不是唯一配置入口。
4. 局部修改只影响必要局部，不允许无理由清空整篇状态。
5. 所有生成结果永不覆盖旧音频。
6. 所有禁用按钮都必须显示明确原因。
7. 任意“未保存修改”都必须可见、可保存、可取消，不允许形成死锁。
8. 所有 CosyVoice 参数严格锁定在 CosyVoice 3.5 Plus 当前真实能力范围内。

---

## 1. 总体工作流

### 阶段一：ChatGPT 真人导演对齐

输入：
- 口播原稿
- 《真人带货口播导演协议》

ChatGPT 输出：
- 一份用户可直接阅读、直接编辑的 Markdown《表演导演方案》
- 不输出机器参数堆砌
- 不要求用户理解 JSON

第一阶段核心只回答：
- 这篇整体怎么演
- 人物状态
- 情绪曲线
- 销售动作
- Phrase 拆解
- 快慢
- 情绪
- 重点词
- 停顿
- 前后衔接
- 哪些地方是价格爆点、强反问、调侃、CTA 等

用户直接编辑这份文档，再发给 ChatGPT 继续讨论。

用户明确说“确认 / 执行第二阶段”后，才进入第二阶段。

### 阶段二：ChatGPT 执行编译

输入：
- 用户最终确认的阶段一导演文档
- 《真人口播执行协议》

输出：
- 唯一严格机器协议：REAL_SPEECH_PERFORMANCE_PLAN_V1
- 只包含吃个糖能解释、能执行或能作为 UI 导演元数据展示的字段
- 不得虚构 CosyVoice 3.5 Plus 不存在的执行能力

用户复制整份协议到“真人口播”输入框。

软件：
1. 解析
2. 严格校验
3. 显示导入预览
4. 用户确认
5. 创建/更新 Phrase 与 Generation Window

---

## 2. 模型能力硬边界

目标模型固定：CosyVoice 3.5 Plus。

### Instruction

本项目双重限制：
- Han count <= 40
- API weighted count <= 100

计数规则：
- Han：权重 2
- 其他 Unicode code point：权重 1
- 不允许用 JS string.length 代替 code point 计数

UI 必须实时显示：
- 汉字 n / 40
- API计数 n / 100
- 是否可生成

任何超限：
- 禁止调用 TTS
- 不自动截断
- 不静默删字
- 给出“让 ChatGPT 精简”快捷入口

### 其他参数

所有可执行参数必须来自 CosyVoice 3.5 Plus 当前真实支持能力和范围。
程序本地做最终校验。
ChatGPT 的输出不能绕过校验。

导演元数据和模型参数严格分离：
- “强反问 / 调侃 / 戳痛点 / 价格爆点”等属于导演语义
- 只有真实可执行字段才能进入 TTS 请求

---

## 3. 表演数据模型

原则：

> 导演做到词，控制做到短语，生成保持连续。

层级：

1. Performance Arc：整篇表演曲线
2. Sales Beat：销售动作
3. Phrase：用户主要编辑单位
4. Word Cue：少量关键词锚点
5. Generation Window：真实 TTS 请求单位

Phrase ≠ Generation Window。

UI 可以逐 Phrase 编辑。
底层可以把相邻 Phrase 合并到同一个 Generation Window，以保持自然连续。

---

## 4. Phrase 必须可人工编辑

每个 Phrase 卡片至少包含：

- Phrase ID（稳定 ID）
- 原文
- 合成文本
- 销售动作
- 表演方向
- Pace
- Energy
- Sales Pressure
- 关键词/重点词
- 停顿意图
- Pronunciation
- 当前 Generation Window
- 当前可执行 instruction
- 高级参数折叠区

每个可编辑字段都必须具备：
- dirty 状态
- 保存
- 取消
- 保存后明确反馈

禁止：
- 用户已经编辑，但“保存”按钮仍无故灰色
- 用户修改后无法判断是否已经生效
- 修改后必须重新导入整份 ChatGPT 方案

---

## 5. 单段修改与重新生成

这是 P0 流程。

正确流程：

修改本段
→ 保存修改
→ 该 Phrase / Window 标记 dirty
→ “重新生成本段”可用
→ 调用 TTS
→ 新结果写入新 revision
→ 试听
→ 可选“设为当前版本”

不允许：

修改某段
→ 全局 rehearsalPassed=false
→ 所有正式生成按钮锁死
→ 强制重新跑开头试演

局部修改只允许使依赖该局部的结果失效。

---

## 6. 取消全局试演死锁

第一次任务：
- 可以建议先生成 1 个代表性 Window
- 可以叫“首段试演”或“先生成这一段”
- 通过后继续批量

但它不是永久全局 Gate。

局部修改之后：
- 不要求重新验证无关开头
- 只重新生成修改范围

如果修改的是全局 Voice、全局人物风格等真正影响全部结果的设置，才允许提示：
“该修改可能影响全篇，建议重新生成相关窗口”。

---

## 7. 原稿修改

原稿必须真的可修改。

流程：
编辑原稿
→ “保存并重新解析”
→ 本地 diff
→ 尽量保留未变化 Phrase 的稳定 ID、表演参数、历史音频

禁止：
- 改一个字就整篇清空
- 所有 Phrase 重编号
- 所有历史音频失去关联
- Director Plan 无条件全部丢失

只对真正变化的 Phrase 建 revision。

---

## 8. 音频版本管理

任何生成都不得覆盖旧文件。

每个 Phrase / Window 下按时间倒序显示：

- rev
- 生成时间
- 播放
- 打开文件位置
- 设为当前使用
- 当前使用标记
- 生成参数摘要

例如：

rev05 22:13 ▶ 📂 ★当前
rev04 22:08 ▶ 📂
rev03 21:57 ▶ 📂

必须能快速拖入剪映。

---

## 9. 真人听感诊断

Diagnosis 不是强制工作流，是需要时调用的 AI 辅助。

用户两条路径：

### A. 用户知道怎么改
直接改 → 保存 → 重新生成

### B. 用户不知道怎么改
点击：
“问 ChatGPT 优化本段”

或在诊断区：
“保存并复制优化请求给 ChatGPT”

自动携带：
- 当前 Phrase / Window
- 原文与合成文本
- 当前导演参数
- 当前 CosyVoice 参数
- 当前音频版本
- 用户选择的诊断项
- 用户自由描述
- 问题时间位置
- 上下文 Phrase

文字自动复制。
音频文件位置提供快捷打开/附件提示。

禁止要求用户滚回页面顶部寻找导出按钮。

---

## 10. ChatGPT 局部修订

软件必须支持“只更新一个 Phrase / Window”的局部方案。

ChatGPT 返回局部修订时：
- 只修改目标 Phrase / Window
- 显示 Before / After
- 用户确认后应用
- 不影响未涉及 Phrase
- 不要求重新导入整篇方案

---

## 11. 导入方案后允许完全人工接管

导入只是初始化。

导入后以下字段必须能由用户自行修改：
- 表演方向
- 销售动作
- pace
- energy
- sales pressure
- emphasis
- synthesis text
- pronunciation
- instruction
- 真实支持的高级参数

人工修改优先于旧 ChatGPT 导入值。

---

## 12. CosyVoice Compiler

软件内建立独立 Compiler。

输入：
- 导演语义
- Phrase / Window
- Word Cue
- 用户高级设置

输出：
- CosyVoice 3.5 Plus 合法 request

职责：
- instruction 压缩与硬校验
- rate/pitch/volume/seed 等范围校验
- pronunciation
- SSML / break（仅真实需要时）
- Window 组合
- 冲突检测

禁止：
- 把所有导演字段机械拼进 instruction
- 每个词机械设置 rate/pitch
- 每个逗号固定 break
- 使用模型不支持字段

## 13. UI 原则

主界面围绕 Phrase 卡片，而不是围绕“协议流程”。

顶部：
- 任务信息
- 原稿
- 保存并重新解析
- Voice
- 全局风格
- 导入 ChatGPT 方案

Phrase 卡片：
- 直观看懂
- 常用字段直接编辑
- 高级参数折叠
- 保存修改
- 重新生成
- 问 ChatGPT
- 历史版本

底部/顶部批量：
- 生成所有未生成
- 生成所有 dirty
- 生成选中
- 拼接当前使用版本

---

## 14. 按钮与状态机硬规则

任何按钮 disabled 时，必须在按钮附近给出人话原因，例如：
- “请先保存本段修改”
- “Instruction 超过 100 加权字符”
- “未选择复刻音色”
- “当前请求结果未知，请先核对计费”

禁止只有灰色按钮、无解释。

任何 dirty 状态都必须有出口：
- 保存
- 取消

任何保存成功都必须有反馈。

任何生成失败都不能让整个任务不可继续。

---

## 15. 表达指纹库

不是本版本启动依赖。

前期主要依赖：
- ChatGPT 文案理解
- ChatGPT 带货表演导演能力
- 用户人工判断

后续用户标记：
- 满意
- 可发布
- Golden

才允许沉淀为高质量表达经验。

失败结果不得混入 Golden 数据。

本版本优先保证：
“表达指纹库为空时，整个系统仍完整可用”。

---

## 16. P0 防低级流程 Bug 验收矩阵

以下任何一条失败，都不得发布“修复版2”。

### 创建
- 新建任务可保存
- 选 Voice 后可继续
- 原稿非空可创建

### 导入
- 阶段二协议可粘贴
- 可校验
- 可预览
- 可确认
- 导入失败不破坏当前任务

### 编辑
- 修改原稿 → 保存按钮启用
- 修改 Phrase 表演方向 → 保存按钮启用
- 修改 instruction → 保存按钮启用
- 修改高级参数 → 保存按钮启用
- 取消修改 → 恢复已保存值

### 单段生成
- 新任务可生成第一段
- 修改第一段后可重生成第一段
- 修改中间段后可重生成中间段
- 不强制重跑无关试演
- 生成新版本不覆盖旧版本

### 诊断
- 可保存诊断
- 可“保存并复制给 ChatGPT”
- 不需要滚回页面顶部
- 可针对单段导出上下文

### 局部 ChatGPT 修订
- 可只更新一个 Phrase
- 未修改 Phrase 不变
- 更新后可直接重生成

### 原稿修改
- 修改一个 Phrase 的文字
- 保存并重新解析
- 未变化 Phrase 尽量保持 ID 和历史
- 变化 Phrase 建新 revision
- 流程仍可继续

### 音频历史
- 同段连续生成 3 次
- 3 个文件都存在
- 页面倒序显示
- 任意版本可播放
- 任意版本可设为当前
- 可打开所在文件夹

### 锁死保护
- 任意编辑状态都不能出现“既不能保存又不能生成又不能取消”
- 任意失败状态都有明确恢复路径
- 不允许局部修改导致全任务永久不可生成

## 17. 回归要求

真人口播修复不得破坏：
- 音频生成
- 复刻音色
- 转文字
- 视频生成
- 一键生成
- 一键复刻
- 资产库
- 设置
- 现有数据库

所有旧功能至少完成现有自动化回归。

---

## 18. 开发顺序

1. 状态机与数据模型
2. 自动化流程测试
3. 原稿局部 diff
4. Phrase 编辑器
5. 单段生成与版本管理
6. Diagnosis 就地 ChatGPT 入口
7. 阶段二协议解析
8. CosyVoice Compiler
9. UI 清理
10. 回归测试
11. Windows 实机验收

原则：
先保证流程永远走得通，再优化视觉和高级能力。
