# 阶段二｜真人口播执行编译 V1.0

## 前提

只有用户已经确认阶段一《真人口播表演导演方案》后才能执行。

输入应包含：

1. 原始口播全文；
2. 用户最终确认的阶段一 Markdown；
3. 本指令文档。

本阶段不再重新创作销售逻辑。任务是把确认好的“人类导演语言”编译为吃个糖 Agent 可导入的唯一 JSON。

## 唯一输出 Schema

`REAL_SPEECH_PERFORMANCE_PLAN_V1`

最终回复只能有一个 JSON code block。可以在 code block 前用一句话说明“已按确认稿编译”，但不得再输出第二份 JSON。

## 模型锁定

目标模型必须固定：

`cosyvoice-v3.5-plus`

严禁输出模型不存在的执行参数。

### 当前执行边界

- instruction：服务端加权长度 <= 100；本项目 Han <= 40；
- rate：0.5～2.0；
- pitch：0.5～2.0；
- volume：0～100，整数；
- seed：0～65535，整数；
- format：软件固定 WAV；
- sample rate：软件固定 48000；
- pronunciation：仅按软件真实支持的 hot_fix 拼音结构；
- 精确停顿：仅通过软件允许的 rhythmBreaks 编译成 SSML break；
- 不得自行发明“情绪值”“销售值”等 API 字段。

导演元数据（salesAction、direction、pace、energy、emphasis、pauseAfter）可以保留给 UI 和后续 ChatGPT 诊断，但不会直接作为 API 字段发送。

## Phrase 规则

- 必须逐字覆盖原稿；
- `phrases[].text` 顺序拼接后必须与 `sourceText` 完全一致；
- 不得改字、删字、补字；
- Phrase 是自然表演短语，不是逐字切分；
- Phrase ID 从 P001 连续编号。

## Generation Window 规则

- Window 才是真实 TTS 请求单位；
- 一个 Window 可以包含多个 Phrase；
- Window 必须按顺序覆盖全部 Phrase 且不重复；
- 优先连续生成，只有人物状态、销售动作或韵律明显改变时才拆 Window；
- 不要为了“控制精细”把每句话都拆成独立请求；
- Window ID 从 GW001 连续编号。

## Instruction 编译原则

Instruction 只放当前 Window 最重要的 1～3 个表演要求。

优先级通常为：

1. 人物 / 场景状态；
2. 当前最关键的情绪或销售动作；
3. 关键快慢、强调或收尾方式。

不要把阶段一全部描述拼进去。

输出前必须自己检查，但软件仍会二次硬校验。

## rate / pitch / volume / seed

只在确有必要时偏离默认值：

- 默认 rate = 1.0
- 默认 pitch = 1.0
- 默认 volume = 50
- 默认 seed = 0

优先让 instruction 和模型自然韵律工作。不要用参数过度编程真人感。

## 停顿

自然标点优先。

只有阶段一明确要求且自然韵律难以稳定实现的关键停顿，才写入 `rhythmBreaks`。

`rhythmBreaks`：

```json
{"afterPhraseId":"P002","pauseMs":220}
```

不要每个逗号都加 break。

## 输出 JSON 结构

```json
{
  "schema": "REAL_SPEECH_PERFORMANCE_PLAN_V1",
  "protocolVersion": "1.0",
  "targetModel": "cosyvoice-v3.5-plus",
  "planId": "unique-readable-id",
  "sourceText": "必须逐字等于用户原稿全文",
  "globalDirection": "阶段一确认后的整篇人物与表演基线，简洁记录",
  "phrases": [
    {
      "phraseId": "P001",
      "text": "原文的一段，逐字保真",
      "salesAction": "强反问钩子",
      "direction": "用用户能理解的人话记录确认后的具体演法",
      "pace": "FAST",
      "energy": "HIGH",
      "emphasis": ["谁不知道"],
      "pauseAfter": "SHORT"
    }
  ],
  "windows": [
    {
      "windowId": "GW001",
      "phraseIds": ["P001"],
      "instruction": "真人面对镜头强反问，快而不喊，带点调侃。",
      "rate": 1.08,
      "pitch": 1.0,
      "volume": 50,
      "seed": 0,
      "transitionPauseMs": 0,
      "pronunciation": [],
      "rhythmBreaks": []
    }
  ],
  "missingInputs": []
}
```

### 枚举

`pace`：`SLOW | NORMAL | FAST`

`energy`：`LOW | MEDIUM | HIGH`

`pauseAfter`：`NONE | SHORT | MEDIUM | LONG`

## 缺失信息

只有缺失信息会导致无法安全编译时才写入 `missingInputs`。

不要猜：

- 产品名特殊读法；
- 用户明确要求确认的发音；
- 不确定的数字或英文读法。

如果存在关键缺失信息，不要伪造 pronunciation。

## 最终自检

输出前必须检查：

1. sourceText 与原稿逐字一致；
2. Phrase 文本拼接后逐字等于 sourceText；
3. Window 按顺序完整覆盖所有 Phrase；
4. 每个 Instruction Han <= 40；
5. 每个 Instruction API加权 <= 100；
6. rate/pitch/volume/seed 全在范围内；
7. 没有不存在的模型字段；
8. 没有把阶段一导演分析重新改写成另一套方案。
