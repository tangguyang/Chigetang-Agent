# 吃个糖 Agent v1.2.9｜真人口播表演生产系统 使用手册 V5.0

> 工作台顶部 📄 打开的必须是当前软件打包的这一版。

# 修复版操作补充（软件 V1.2.9）

任务创建成功后可在“任务信息”修改名称、目标、原稿和音色，点击“保存任务信息”。新建表单会清空；未保存修改会阻止生成和导出。

试演必须对应当前音色、指令、速率和Unit范围。旧参数试演只能试听，不能为新方案放行；重做试演后需要再次确认。

点击“已试听，基础方向通过”，随后“生成本段／完整口播（新版本）”。音频生成后试听、确认满意，再拼接完整WAV。灰色按钮附近会说明缺少哪个步骤。

“一键导出给ChatGPT”默认只复制文字，显示两秒“已复制”，不打开文件夹。详细导演节拍是参考；实际模型执行的是窗口instruction等参数。

资产库统一检索生成任务与结果；音频内包含试演、片段和成品。删除口播工作任务保留音频，使用“结果资产／本地素材”查看来源已删除的音频。未知请求需要先核对计费，恢复下载不会自动重生成。

# 1. 你只需要做什么

你只负责：

1. 选音色、给台词；
2. 听结果；
3. 勾选哪里不对；
4. 看软件准备的变更，确认是否应用。

你不需要懂声音工程。

# 2. 与「音频生成」的区别

「音频生成」继续保留原功能。

「真人口播」是独立模块，专门把 30～90 秒短视频台词做成像真人一次录完的口播。

真人口播出错不应该影响音频生成。

# 3. 本版本不需要新的 AI API

ChatGPT 就使用你现在的 ChatGPT。

流程：

```text
软件导出任务
→ 你粘贴给 ChatGPT
→ ChatGPT 做导演/诊断
→ 返回固定 JSON
→ 软件校验后执行
```

# 4. 顶部两个文档

```text
[📄 使用手册] [🔒 ChatGPT返回协议]
```

📄：你现在看的使用方法。  
🔒：规定 ChatGPT 返回软件时必须怎么写，防止软件识别错。

正常使用不用每次上传完整协议；软件导出的 Task 已带关键要求。

# 5. 三种模式

- ChatGPT导演（推荐）
- 连续一镜到底（手动）
- 导演分段（手动）

# 6. 正式生产流程

```text
选音色
→ 粘贴台词
→ 一键导出给 ChatGPT
→ 导入 ChatGPT 导演方案
→ 看变更预览
→ 应用
→ 试演
→ 听
→ 不满意：小白听感诊断
→ 一键导出诊断给 ChatGPT
→ 导入修复方案
→ A/B
→ 全文
→ Golden Sample
```

# 7. 一键导出给 ChatGPT

软件会自动准备：

- 台词；
- Unit ID；
- 当前参数；
- Instruction；
- 前后上下文；
- 问卷；
- 修改历史；
- 当前协议要求；
- 当前仅复制任务文字；WAV需用“导出诊断 + WAV”单独准备并附给ChatGPT。

你一般只需要：

```text
Ctrl+V
→ 如有WAV就拖进去
→ 发送
```

# 8. ChatGPT 返回怎么导入

复制 ChatGPT 整个回复。

回软件点：

```text
导入 ChatGPT 方案
```

软件只执行最后的协议 JSON，不执行自然语言解释。

执行前一定会给你看：

- 改什么；
- 原来是什么；
- 新值是什么；
- 哪些保持不变；
- 哪一段会重生成。

你确认后才执行。

# 9. Instruction 最重要的硬限制

所有情绪/表演 Instruction 必须同时满足：

```text
汉字 <= 40
API加权计数 <= 100
```

官方计数：

- 汉字 = 2；
- 标点/英文/数字/空格等 = 1。

软件自己算，不相信 ChatGPT 自己报数。

输入框会显示：

```text
汉字 27 / 40
API计数 59 / 100
```

超任一限制：

> 不能生成。

不要自己截断，点：

```text
复制精简请求
```

让 ChatGPT 保持原意压缩。

# 10. 为什么限制 40 个汉字

100 是 API 的加权硬上限。

40 个汉字是本项目额外安全上限，用来防止：

- ChatGPT 写成长篇导演说明；
- 需求互相冲突；
- 过长 Instruction 更容易超限；
- 每个 Window 的核心表演意图不清楚。

通常 18～32 个汉字就够。

# 11. 五个概念

- Speaker Profile：这个人平时怎么说。
- Performance Arc：这条视频从头到尾状态怎么变化。
- Performance Beat：一个表达动作。
- Generation Window：真正一次送给 CosyVoice 的范围。
- Repair Window：哪里不好时，真正重做的自然范围。

**Beat 可以细，但生成不要机械切碎。**

# 12. 试演

建议先做 8～15 秒。同一窗口内有效短试演（例如7.8秒）也可在试听后确认通过，无需调慢或补静音。

先确认：

- 像不像真人；
- 像不像念稿；
- 有没有播音/广告腔；
- 节奏；
- 发音。

基础方向不对，不急着生成全文。

# 13. 小白听感诊断

你只需选：

- 非常符合
- 基本符合
- 不太符合
- 完全不符合
- 不确定

然后选：

- 第一次哪里不自然；
- 最明显问题；
- 自由感觉。

“说不清，就是觉得假”也可以。

# 14. A/B

修复后只比较：

- A 上一版
- B 当前版

不要一次听十几个版本。

# 15. 同一个问题最多三轮

三轮还没解决，不继续抽卡。

系统应该升级检查：

- 音色源；
- Window；
- 连续/分段；
- 上下文；
- 原文难读点。

# 16. Original Text

原稿锁定。

ChatGPT 协议不能改。

需要发音处理时，改的是 Synthesis Text / Pronunciation。

# 17. 如果网络超时

软件如果不能确定请求到底有没有到 CosyVoice：

> 不会自动再发一次。

会标成：

```text
unknown_result
```

避免重复收费。

# 18. 如果软件崩溃

重启后发现上次还在 generating：

> 标成 interrupted。

不会自动补发新的付费请求。

# 19. Golden Sample

没有明显 AI 违和、发音/拼接没有关键问题、你愿意发布，就可以 Golden。

不要追求所有题都“非常符合”。

# 20. 三篇顺序

```text
置顶一 → 置顶二 → 置顶三
```

第一篇先建立真人基础和固定句；
第二篇解决创始人故事；
第三篇解决专业长句和枚举。

# 21. 最终标准

> 完整听下来，首先感觉是“这个人真的在说”，而不是“AI 在念稿”。
